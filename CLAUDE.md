# CLAUDE.md

Этот файл содержит руководство для Claude Code (claude.ai/code) при работе с кодом в данном репозитории.

## Обзор проекта

Это проект-шаблон для создания плагинов к golangci-lint v2. Основная цель - продемонстрировать, как создавать кастомные линтеры как модули, которые встраиваются в golangci-lint.

Этот линтер проверяет форматирование функциональных сигнатур в Go коде - он анализирует объявления функций, функциональные литералы и методы интерфейсов на предмет соответствия правилам переноса строк. Это сделано намеренно как минимальный пример функциональности. Проект можно использовать как основу для написания собственных правил статического анализа Go кода.

Проект показывает:
- Как регистрировать кастомные линтеры в golangci-lint
- Как обрабатывать конфигурацию плагинов через YAML
- Как работать с AST анализа синтаксиса
- Как писать тесты для кастомных линтеров

## Архитектура

Проект следует архитектуре модулей плагинов golangci-lint:

- `linter.go`: Основная реализация плагина со структурой `PluginLineWrap`
- Регистрация плагина через `github.com/golangci/plugin-module-register/register`
- Структура настроек для обработки конфигурации (`MySettings` с полем `MaxLineLen`)
- Единственный анализатор, который обходит узлы AST для проверяет функциональные сигнатуры на соответствие правилам форматирования
- Режим загрузки установлен в `register.LoadModeSyntax`, так как линтеру не нужна информация о типах

## Основные команды разработки

### Сборка и тестирование
```bash
# Запустить все тесты
go test ./...

# Запустить один тест
go test -run TestPluginExample

# Собрать модуль
go build ./...
```

### Линтинг с golangci-lint
```bash
# Установить плагин и запустить с примером конфигурации
# Использовать .golangci.example.yml как пример
golangci-lint run -c .golangci.example.yml
```

## Конфигурация плагина

Плагин принимает настройки в формате определенном структурой `MySettings`:
- `MaxLineLen`: максимальная длина строки в символах (int)

Пример конфигурации:
```yaml
settings:
  custom:
    line-wrap:
      type: module
      settings:
        max-line-len: 80
```

## Стратегия тестирования

Тесты используют пакет `analysistest` от golangci-lint с тестовыми данными в `testdata/src/testlintdata/todo/`. Тестовый файл содержит примеры функциональных сигнатур для проверки правил форматирования.

## Ключевые детали реализации

- Плагин регистрирует себя с именем "line-wrap", а анализатор называется "linewrap"
- Линтер проверяет форматирование функциональных сигнатур и не использует информацию о типах
- Анализирует три типа узлов AST:
  - `*ast.FuncDecl` - объявления функций (включая методы)
  - `*ast.FuncLit` - функциональные литералы (анонимные функции)
  - `*ast.InterfaceType` - методы интерфейсов
- Генерирует односрочную версию сигнатуры и проверяет её длину относительно `MaxLineLen`
- Поддерживает Go 1.18+ дженерики (type parameters)
- Использует настраиваемый `renderFieldList` для рендеринга параметров, так как `go/printer` не поддерживает `*ast.FieldList` напрямую
- Правильно обрабатывает квадратные скобки для type parameters и круглые скобки для обычных параметров
- Генерирует `analysis.SuggestedFix` с точными позициями для автоматического исправления кода
- Плагин разработан для демонстрации архитектуры модулей плагинов golangci-lint
